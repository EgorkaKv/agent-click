# Журнал решений

Формат: дата, решение, почему, отвергнутые альтернативы. Замещённые решения не удаляем, а помечаем `ЗАМЕЩЕНО → D-N`.

## D-1. Подключение к браузеру через CDP autoConnect, без расширения (2026-10-26)

**Решение.** Подключаемся к уже запущенному Brave пользователя по CDP. Удалённая отладка включается один раз переключателем `brave://inspect/#remote-debugging` («Allow remote debugging for this browser instance»). При каждом подключении браузер спрашивает Allow. Адрес и порт берём из файла `User Data\DevToolsActivePort`.

**Почему.**
- Работает в основном профиле: куки, сессии, всё видно пользователю.
- Доверенный ввод (`Input.dispatchMouseEvent`, `isTrusted=true`) доступен из коробки.
- Весь код в одном процессе.

**Отвергнуто.**
- Флаг `--remote-debugging-port`: в Chromium 136+ не работает с основным профилем.
- Своё MV3-расширение и WebSocket-мост: для доверенного ввода всё равно нужен `chrome.debugger` с той же плашкой «браузер отлаживается», а кода примерно вдвое больше.
- Headless или отдельный профиль: нет кук пользователя, действия не видны.

**Последствия.** Allow подтверждается на каждое подключение. Пока работаем одним процессом, это происходит раз за сессию Claude Code. Если станет мешать, можно перейти на демон (см. открытые вопросы в architecture.md).

**Статус окружения (2026-10-26).** Brave 1.98.60 / Chromium 156: функция поддерживается (появилась в Chromium 144). Переключатель у пользователя пока не включён: нет `DevToolsActivePort`, нет ключа `remote_debugging` в `Local State`.

## D-2. Язык: TypeScript, не Rust (2026-10-26)

**Решение.** Сервер пишем на TypeScript (Node 22). Библиотеки: `@modelcontextprotocol/sdk`, `puppeteer-core` (CDP), `sharp` (метки и JPEG).

**Почему.** Время шага агента определяют модель (3–15 с) и загрузка страницы (0,3–3 с). Скриншот кодирует сам браузер. Сбор элементов в любом случае выполняется как JS внутри страницы. Rust сэкономил бы около 10 мс на обработке картинки, это меньше 1% шага. В TS эталонный MCP SDK и зрелая CDP-библиотека.

**Отвергнуто.** Rust (`rmcp`, `chromiumoxide`): выигрыша на горячем пути нет, CDP-экосистема слабее, итерации медленнее. Единственный плюс, один бинарник, для личного инструмента неважен.

**Уточнение (2026-10-26).** Логи прошлых сессий показали, что в Claude in Chrome инструмент выполнялся 5–10 с на batch, дольше паузы модели (3–4 с). Источник задержек — паузы и ожидания внутри инструмента, а не язык. Решение остаётся в силе (см. research/usage-history.md).

**Принцип скорости.** Скорость получаем архитектурно: меньше циклов «вызов → ответ», меньше токенов, никаких фиксированных пауз.

## D-3. Метки рисуются на скриншоте на стороне сервера (2026-10-26)

**Решение.** Скриншот снимается чистым, номерные метки накладываются в сервере (`sharp`), а не через оверлеи в DOM.

**Почему.** Пользователь не видит мерцания, страница и вёрстка не меняются.

## D-5. Действия выполняются одним инструментом `act` со списком шагов (2026-10-26)

**Решение.** Все действия (click, fill, select, check, press, scroll, upload, wait_for, expect) — это шаги одного инструмента `act(steps)`. Один шаг — частный случай.

**Почему.** Батч — естественный режим работы, агенты и так им пользовались. Отдельные инструменты возвращают лишний цикл «вызов → ответ» на каждый шаг. Батч осмыслен потому, что цель можно указать текстом и каждый шаг проверяется. Самоотчёт 3bbafecf: батчить было нечего, пока каждый шаг требовал свежий ref.

**Отвергнуто.** Отдельные `click`/`fill`/`select` + `batch`.

## D-6. Скриншоты: режим auto, но агент может потребовать картинку (2026-10-26)

**Решение.** По умолчанию картинка прикладывается, только когда экран заметно изменился. Агент в любой момент может явно её запросить: `look({image: "always"})` или опция `screenshot: true` у `act`/`navigate`.

**Почему.** Список элементов несёт основной смысл, а картинки дорогие. Но инструмент может ошибиться в оценке «значительного изменения», и агент не должен из-за этого остаться без картинки.

## D-7. Подтверждение рискованных действий — не задача инструмента (2026-10-26)

**Решение.** Инструмент не подтверждает и не блокирует публикацию, оплату и удаление.

**Почему.** Harness Claude Code (классификатор разрешений) уже блокирует такие действия. Логи это подтверждают: отказы на Save и DELETE. Задача инструмента — описывать действия семантически («click "Сохранить" in dialog X»), чтобы классификатору было что оценивать. Защиту от подтверждения не того объекта даёт шаг `expect` (проверка текста диалога перед кликом), а не отдельный механизм.

## D-8. `eval` остаётся как последнее средство (2026-10-26)

**Решение.** Инструмент `eval(js)` есть. В его описании для агента прямо сказано: использовать, только если ни один другой инструмент не подходит (диагностика пикселей, consent и т.п.).

**Почему.** Почти всё, ради чего агенты писали JS (109 вызовов в 3bbafecf), закрывают `read`, `fill`, `wait_for`, `read_api` и сетевые запросы в ответе `act`. Без запасного выхода агент застрянет на редких задачах. Записи через `eval` по-прежнему контролирует harness.

## D-9. Сбор элементов (2026-10-26)

Подвопросы перечислены в architecture.md, пункт 2.

- **а) Источник.** Свой JS в странице плюс библиотека `dom-accessibility-api` для имён и ролей по спецификации accname. Отвергнуто: CDP Accessibility (нет геометрии и видимости, тяжело на больших SPA) и CDP DOMSnapshot (нет имён и ролей).
- **б) Интерактивность.** Стандартные теги, роли, tabindex, contenteditable плюс эвристика `cursor:pointer` для div с обработчиками. Вложенные дубли отсекаются: если внутри кликабельного блока есть кнопка, показываем только кнопку.
- **в) Текст.** Интерактивные элементы плюс короткий значимый текст: заголовки, статусы и бейджи, пары «подпись — значение», ячейки строки рядом с её действиями. Длинный текст сворачивается. Почему: агентам постоянно нужны статусы и значения («Черновик», «FAILED», «PLN 244.99»).
- **г) Контекст.** Путь из диалога, landmark-области, заголовка, fieldset или группы и строки таблицы, не глубже трёх уровней. Элементы группируются под общим заголовком контекста, путь у каждого не повторяется.
- **д) Видимость и слои.** Модальный слой по `aria-modal`, `<dialog>` и `inert`. Перекрытие через `elementFromPoint` в нескольких точках. *Нужно проверить на практике.*
- **е) Номера.** Подход Claude in Chrome (WeakRef-карта) плюс отпечаток элемента для повторного поиска после перерисовки. Освободившиеся номера не используются повторно. Подробности ниже.
- **ж) Фреймы.** В MVP: shadow DOM и iframe того же origin. Cross-origin iframe (OOPIF) через отдельное подключение CDP — второй этап.
- **з) Дифф.** Снимки до и после действия сравниваются по номерам. Автоскриншот, если сменился слой или URL либо изменилась заметная доля видимых элементов. *Порог подбирать на практике.*
- **и) Производительность.** Цель — меньше 50 мс на сбор на тяжёлом SPA. Лимит размера вывода, элементы за экраном — сводкой по секциям.

**Подробности по (е).** WeakRef из Claude in Chrome хранит ссылку на конкретный DOM-узел. Он переживает перерисовку, только если фреймворк обновил существующий узел. Если узел пересоздан (смена `key`, условный рендер, dropzone, шаг мастера), ссылка умирает. Логи это подтверждают: «Element has been garbage collected», «ref_stale», один и тот же чекбокс получил номера ref_3382 → ref_4624. Поэтому к WeakRef добавляется отпечаток: роль, имя, путь контекста и порядковый номер среди одинаковых в этом контексте. Если узел умер, элемент ищется заново по отпечатку и получает тот же номер. Если кандидатов несколько или ни одного, инструмент ничего не угадывает и возвращает ошибку с актуальным состоянием.

## D-4. Процесс: один MCP-процесс по stdio для MVP (2026-10-26)

**Решение.** Claude Code запускает сервер по stdio, и сервер сам держит CDP-подключение. Демон с тонким MCP-клиентом откладываем, пока не появится реальная потребность.

## D-10. Структура MVP и порядок сборки (2026-10-26)

**Решение.**
- Модули: `src/page/` (скрипт в странице, собирается esbuild в `dist/page.js` и внедряется в страницу), `src/render/` (текст `look`, дифф, метки на скриншоте), `src/browser/` (подключение, сеть, стабилизация, CDP-ввод), `src/core/` и `src/server.ts` (исполнитель `act`, MCP-инструменты). Контракт между модулями — `src/types.ts`.
- MVP-инструменты: `look`, `act` (click, dblclick, hover, fill, select, check, press, scroll, wait_for, expect), `navigate`, `tabs`, `eval`. Позже: `upload`, `read`, `read_api`, `zoom`.
- Тесты: vitest плюс отдельный headless Brave с временным профилем (`test/helpers/browser.ts`). Профиль пользователя тестами не трогается.
- Служебные слова в выводе инструментов — на английском (`Messages:`, `↓ below:`). Примеры в api-draft.md на русском — иллюстрация, не формат.

**Как строим.** Каркас, контракт и интеграцию (`src/core`, `src/server.ts`) пишет основная сессия. Модули `page`, `render`, `browser` отданы трём субагентам на Haiku 5.5 по подробным ТЗ. Это эксперимент, см. [research/haiku-experiment/](research/haiku-experiment/).

**Окружение.** 2026-10-26 переключатель удалённой отладки у пользователя включён: `DevToolsActivePort` есть, порт 9222.

## D-11. Исправления по первой реальной сессии (2026-10-26)

Разбор: [research/live-session-1.md](research/live-session-1.md).

- **Журнал замеров.** Каждый вызов инструмента пишет строку в `AGENT_CLICK_LOG` (по умолчанию `%TEMP%\agent-click.log`): общее время и фазы (`connect`, `attach`, `inject`, `snapshot`, `locate`, `settle` с причиной таймаута, `screenshot`, `marks`, шаги `act`). Почему: по транскрипту нельзя отделить время сервера от накладных расходов Claude Code.
- **Сеть.** Запросы не по http(s) (расширения, `data:`, `blob:`) не учитываются вовсе. Запросы, заблокированные клиентом (Brave Shields, блокировщики), не считаются провалом. Хосты телеметрии совпадают и с префиксом через дефис (`browser-intake-datadoghq.eu`). Мутации на другой сайт (сравнение по регистрируемому домену, приближённо) скрыты, если успешны; если провалились — показываются с пометкой `third-party, ignored` и шаг не валят. Отвергнуто: валить шаг на любой провал — ложные провалы из-за чужой телеметрии.
- **`scroll` проверяет сдвиг.** Ложный «✓» запрещён. `to: <элемент>` сравнивает позиции прокрутки до и после; если ничего не сдвинулось и элемент вне экрана — ошибка, если уже на экране — `(already in view)`. `top`/`bottom`/пиксели без `in` прокручивают документ, а если он не прокручивается — самый большой видимый прокручиваемый контейнер. С `in` прокручивается ближайший прокручиваемый предок этого элемента (прямое `scrollTop`, не колесо мыши). Упор в край — `(already at the bottom of …)`, а не ошибка.
- **`tabs`** принимает `match` — подстроку URL или заголовка; при нескольких совпадениях ошибка со списком. `list` показывает заголовки.
- **Скрипт страницы** (scope по landmark, имена безымянных контролов, числовые заголовки, дубль статуса в Messages) — задача для нового агента Haiku: [research/haiku-experiment/task-e-page-fixes.md](research/haiku-experiment/task-e-page-fixes.md).
- **Инструмент `read`** (`PageApi.read`, [src/page/read.ts](../src/page/read.ts)): текст области без номеров и отбора — заголовки `#`, таблицы строками `| a | b |`, значения полей `[значение]` (имя повторяется, только если у поля нет видимой подписи), флажки ☑/☐; скрытое пропускается. Область по умолчанию — открытый диалог, иначе `main`, иначе `body`; лимит 20 000 символов. Почему: в реальной сессии все 7 вызовов `eval` были чтением текста или таблиц.
- **Messages.** Источник сообщения не повторяется в Messages, только если он уже в списке элементов и строчный (`span role=status` — бейдж). Блочные статусы и тосты остаются сообщениями.

## D-12. Исправления по обходу Meta Ads и Perplexity (2026-10-26)

Список багов: [research/test-tasks.md](research/test-tasks.md), раздел «Баги, найденные во время обхода». Журнал замеров этого обхода: `look` 0,26 с, `tabs switch` 0,65–0,75 с, клик 1,1–1,6 с (из них ожидание стабилизации 0,4–2 с). Сервер больше не узкое место; первые две попытки подключения ушли в таймаут 60 с, пока пользователь не нажал Allow.

- **Новая вкладка после шага `act`.** Учитывается любая новая вкладка (у ссылок с `rel=noopener` нет opener, по нему сравнивать нельзя). Если шаг открыл вкладку, `act` переключается на неё, как сам браузер, останавливает пакет («the rest was meant for the old tab») и вместо диффа возвращает `look` новой вкладки. Отвергнуто: только сообщать `! new tab opened` — агент всё равно идёт туда следующим вызовом, а номера старой страницы в новой бессмысленны.
- **Дифф перекрытий.** Если у 3+ элементов одинаково изменился `occludedBy` (модалка, оверлей загрузки), это одна строка `~ N elements now covered by X` / `no longer covered by X`; прочие изменения этих элементов остаются.
- **Сеть в выводе `act`.** Одинаковые запросы схлопываются (`POST /api/graphql/ ×22 → 200`), не больше 6 строк, ошибки всегда первыми.
- **Стабилизация.** Картинки и шрифты не считаются загрузкой; скрипты и стили — только первые 3 с (ленивый чанк после клика ждём, сотни скриптов Ads Manager — нет). В описании ожидания сначала запросы данных, потом статика.
- **Скрипт страницы** (секция по ближайшему заголовку только если он над элементом в той же колонке, мусор в именах, дубли причин загрузки, Perplexity) — новому агенту Haiku: [research/haiku-experiment/task-f-page-fixes.md](research/haiku-experiment/task-f-page-fixes.md).

## D-13. Исправления по живой сессии 2: черновик кампании в Ads Manager (2026-10-26)

Разбор и список из 23 багов: [research/live-session-2.md](research/live-session-2.md). Журнал замеров: больше половины скриншотов на Ads Manager не укладывались в 3 с (удачные — 1,2–2,4 с), картинка молча пропадала.

- **Безопасность `select`.** При неудаче `select` больше не нажимает Escape: если список не открылся, Escape уходит странице (в Ads Manager закрывает редактор и предлагает «Опубликовать черновики?»). Список остаётся открытым, агент видит его в диффе.
- **`select` ждёт список** до 3 с после клика и после ввода (опрос `openOptions`), а не сдаётся после стабилизации. Текст для фильтра вводится вместо содержимого поля (выделить всё → ввод), не дописывается.
- **Неоднозначная опция — ошибка** со списком совпадений, как для любой цели. Точное совпадение (без регистра) важнее подстроки.
- **Виртуализированный список.** Если опции нет среди отрисованных, `select` прокручивает список с начала шагами и ищет снова (до 40 шагов).
- **Ввод по клавишам.** `combobox`/`searchbox` до 60 символов заполняются посимвольно (`keyDown`/`keyUp` с текстом), остальные поля — `Input.insertText`. Почему: автокомплит Meta реагирует только на события клавиш. Такое поле после `fill` не теряет фокус, иначе подсказки закрываются. Отвергнуто: всегда по клавишам — две CDP-команды на символ, длинные тексты медленно.
- **Повтор поиска цели.** Цель, заданная текстом, ищется повторно до 1,5 с, если её ещё нет (календарь, список после клика). Номер не ищется повторно: он либо есть, либо нет.
- **Отменённые запросы** (`net::ERR_ABORTED`, `canceled`) не валят шаг и показываются как `cancelled by the page`: SPA отменяет запросы при переходе.
- **`fill` и числа.** `"10"` → `"10,00"` — та же сумма: показывается фактическое значение без ⚠.
- **`scroll`.** Пиксели — сдвиг на N (описано в инструменте). `to: <элемент>` после стабилизации проверяет, что элемент в окне (страницы с виртуализацией возвращают прокрутку). С `in` берётся ближайший прокручиваемый предок, который ещё может сдвинуться в нужную сторону (вложенные списки). Элемент в `in` может быть disabled — он только ориентир (`locate(..., {anyState})`).
- **Дифф.** База диффа — последний обычный `look`; `look` со `scope` или `full` её не меняет. После прокрутки исчезнувшие элементы — одна строка `↕ N out of view after scrolling: …`, а не «−» по каждому. Если шаг увёл на другой путь URL, `act` возвращает состояние новой страницы (как `look`), а не дифф.
- **Стабилизация** ждёт коротких CSS-анимаций и переходов (конечные, ≤ 3 с; бесконечные — это спиннеры): раскрытие панели не меняет DOM, но содержимое ещё не на месте. Причина таймаута при зависших пробах — «page busy or navigating», а не «not responding».
- **Скриншот:** таймаут 8 с; если кадра нет — строка `(no screenshot: …)`. Метки рисуются по рамкам, снятым сразу после кадра, а не по снимку до него.
- **Передача аргументов в страницу.** Пропущенный необязательный аргумент больше не превращается в `null` (JSON): из-за этого `read` и `expect` без `scope`/`in` падали с `reading 'replace'`.
- **Скрипт страницы** (номер при смене имени ссылки/строки, scope по заголовку, контекст «сдвинут на один», склейка и дубли в именах, подпись опций, время в Messages) — новому агенту Haiku: [research/haiku-experiment/task-g-page-fixes.md](research/haiku-experiment/task-g-page-fixes.md).
