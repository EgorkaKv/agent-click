# Первая реальная сессия на agent-click (2026-10-26)

Задача пользователя: проверить связку RevenueCat → AppsFlyer → Meta для flowr (только чтение). Сессия `aa9e67ce`, 33 вызова agent-click за ~5 минут. Самоотчёт агента: [self-reports/flowr-attribution-check.md](self-reports/flowr-attribution-check.md). Задача выполнена, агент нашёл реальные проблемы настройки (нет iOS-платформы в Meta, пустой sandbox-ключ AppsFlyer).

Из транскрипта не отличить время сервера от накладных расходов Claude Code (подтверждение разрешений и т.п.) — **нужен журнал замеров на стороне сервера**.

Известная причина медленного `act`: ожидание стабилизации ждало запрос расширения браузера (`ghmbeldphafepmbegfdlkpapadhbakde/dropdown.html`, `chrome-extension://`) и уходило в таймаут 5 с.

## Проблемы

| # | Проблема | Где | Источник |
|---|---|---|---|
| 1 | Запросы расширений (`chrome-extension://`) считаются запросами страницы → таймауты стабилизации | browser/network | транскрипт |
| 2 | Ложный провал шага: `POST browser-intake-datadoghq.eu … ERR_BLOCKED_BY_CLIENT` (Brave Shields заблокировал телеметрию), хотя клик сработал. Хост не попал в список (`browser-intake-datadoghq.eu` ≠ `*.datadoghq.eu`); заблокированные клиентом и сторонние запросы не должны валить шаг | browser/network, core/act | самоотчёт |
| 3 | `scroll` во внутреннем контейнере: `to: <элемент>` → «✓», но ничего не сдвинулось; `to: "bottom"` без `in` → документ не прокручивается. Ложный успех | core/act | самоотчёт |
| 4 | `look({scope: "main"})` → «scope not found», хотя в выводе есть группа `[main]` | page | самоотчёт |
| 5 | Переключатели без подписи: `[20] clickable` на месте «Activate partner», состояние switch-ей пришлось читать через `eval` | page | самоотчёт |
| 6 | Чтение текста/таблиц через `eval` (маппинг событий AppsFlyer, атрибуты клиента) — нет инструмента `read` | новый инструмент | самоотчёт |
| 7 | `tabs switch` только по номеру; агент промахнулся при 12 вкладках. Нужен выбор по подстроке URL/заголовка | core/server | самоотчёт |
| 8 | Шум: KPI-цифры как заголовки секций (`section "0"`, `section "$0"`), бейдж `status "id6792269704"` в `Messages` | page | транскрипт |

## Что сработало (по самоотчёту и транскрипту)

- `look full` прочитал форму из ~50 полей с значениями за один вызов.
- `act` сам сообщает, куда перешли, отдельный `look` после клика не нужен.
- `! new tab opened` после клика — без него результат клика был бы потерян.
- Номера стабильны между вызовами (агент кликал по номерам из предыдущих ответов без ошибок).
