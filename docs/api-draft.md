# Черновик API инструментов (v1)

Статус: черновик. Принятые решения — в [decisions.md](decisions.md): D-5 (один `act`), D-6 (картинки), D-7 (без подтверждений в инструменте). Основание: [research/usage-history.md](research/usage-history.md), включая самоотчёты сессий, и [research/claude-in-chrome.md](research/claude-in-chrome.md).

**Изменения v0 → v1:**
- добавлены флаг готовности страницы и признаки загрузки;
- добавлены слои: открытый модальный диалог;
- добавлены перекрытия, неактивные вкладки, раздельные подписи для полей с одинаковым названием;
- `fill` и `select` сравнивают запрошенное значение с фактическим;
- в ответе на действие приходят изменяющие сетевые запросы с текстом ошибки;
- новый шаг `expect`;
- новый инструмент `read_api` (только GET).

## Принципы

1. **Действие возвращает результат.** Каждое действие само ждёт, пока страница успокоится, проверяет эффект и возвращает изменения. Инструмента `wait` нет.
2. **Никакого тихого успеха.** Если клик ничего не изменил, это ошибка. Если `fill` дал не то значение, это предупреждение. Если ожидаемый диалог не открылся, батч останавливается. *(Самоотчёт 32ce617b: «половину вызовов я тратил на проверку».)*
3. **Номер, текст или подпись вместо координат.** Номера на скриншоте и в списке совпадают. Если под указание подходит несколько элементов, инструмент возвращает ошибку со списком кандидатов и ничего не угадывает.
4. **Видно то, что видит пользователь.** Если открыт модальный диалог, показываются только его элементы. Перекрытые элементы помечаются. Состояние «загружается» явно отличается от «пусто».
5. **Правда о результате — из сети, а не только с экрана.** Статусы изменяющих запросов и текст ошибок приходят в ответе на действие. Read-only доступ к API сайта — отдельным инструментом.
6. **Картинка в режиме auto, но агент может её потребовать** (D-6).

## Инструменты

### `look({ scope?, image?, full? })`
Состояние страницы.
- `scope`: номер или текст контейнера (`"dialog"`, `"Черновики"`, `21`).
- `image`: `auto` (по умолчанию) | `always` | `never`.
- `full: true`: элементы всей страницы, только текстом.

```
Tab 1/3 · App Store Connect — Flowr · appstoreconnect.apple.com/apps/…/distribution/…
Viewport 1440×900 · scroll 0/2400 · ⏳ loading (2 requests, spinner in "Сборка")
Layer: dialog "Добавить фазу" (страница под ним заблокирована)

[dialog "Добавить фазу"]
  [40] combobox "Тип" = — ⚠ "Select an option"
  [41] textbox "Длительность" = "3"
  [42] combobox "Единица" = "Months"
  [43] button "Apply" (disabled)
  [44] button "Cancel"
Сообщения: toast "Your changes have been saved"
```

На странице без диалога:
```
[header] [3] combobox "Рекламный аккаунт" = "Rostemo (act_1234…)"
[main › tablist] [30] tab "Описание" (selected) · [31] tab "Видео и снимки экрана" (12 элементов внутри)
[main › section "Информация для проверки" › group "Контактная информация"]
  [51] textbox "Имя" = "Yehor" (id contactFirstName)
  [52] textbox "Телефон" = "" (placeholder "+48…")
  [53] combobox "Локаль" = "pl" (50 options)
[main › footer (sticky)] [60] button "Сохранить" (disabled)
↓ ниже: section "Версия" (8), section "Сборка" (3)
```

Правила формата:
- **Шапка ответа:** вкладка, URL, viewport, прокрутка. Строка готовности: `✓ settled` или `⏳ loading` с причиной (запросы в работе, спиннер, скелетон). Активный слой.
- **Подпись поля** берётся из label, aria, placeholder, заголовка группы. Если внутри области несколько полей с одинаковой подписью, добавляется различающий признак (`id`, `name`, `placeholder`).
- **Состояние:** value, checked (☑/☐), selected, expanded, disabled, invalid и текст ошибки, количество вариантов в списке. Пункты списка не перечисляются, пока он не открыт.
- **Перекрытые элементы** помечаются (`occluded by footer`). Для неактивных вкладок показывается только число элементов внутри.
- **Отдельный блок «Сообщения»:** toast-уведомления, баннеры, ошибки валидации.
- **Шапку сайта** с переключателями аккаунта показываем всегда.

### `act(steps, { screenshot?: "auto" | true | false })`
Шаги выполняются по порядку. Перед каждым шагом инструмент находит цель, после шага ждёт, пока страница успокоится, и проверяет эффект. Если эффекта нет или он неожиданный, батч останавливается.

Цель — номер (`12`), текст (`"Далее"`) или текст в области (`{ text: "Add phase", in: "Phases" }`).

| Шаг | Что делает |
|---|---|
| `{ click: t }` / `dblclick` / `hover` | Прокрутить к элементу, проверить перекрытие, доверенный CDP-клик. Нет видимого эффекта и запросов — ошибка |
| `{ fill: { 14: "50", "Описание": "…" } }` | Очистить, ввести (нативный setter или insertText), зафиксировать (blur). Сравнить введённое с итоговым: `requested 199.99 → actual "PLN 244.99"` ⚠ |
| `{ select: [t, "EUR"] }` | Нативный или кастомный список, поле с подсказками. Открыть, дождаться окончания анимации меню, при необходимости ввести запрос, выбрать пункт по тексту, проверить значение. Один автоматический повтор, затем ошибка |
| `{ check: [t, true] }` | Чекбокс, radio или switch с проверкой итогового состояния |
| `{ press: "Enter" }` | Клавиша или сочетание клавиш |
| `{ scroll: { in?: t, to: "bottom" \| t \| px } }` | Прокрутка страницы или контейнера |
| `{ upload: [t, ["C:/…/a.png", …]] }` | `DOM.setFileInputFiles` по пути. Перед каждым файлом заново находит input (dropzone его пересоздаёт). Порядок сохраняется. Ответ: появился ли файл на странице, статусы запросов, ошибки сайта |
| `{ wait_for: { text? \| gone? \| url? \| enabled? \| request? }, timeout? }` | Ждать условия, а не времени |
| `{ expect: { text?, in?, url?, value? } }` | Проверка без действия. Не выполнена — батч останавливается. Пример: перед «Удалить» проверить, что диалог содержит «язык: польский» |

Ответ:
```
✓ fill [14] "Дневной бюджет": "50" → "50,00"
✓ click [17] "Далее" → opened dialog "Создание рекламы" (шаг 2/3)
    POST /v20.0/act_1234/adsets → 200
✗ click "Сохранить": no visible change
    PATCH /iris/v1/appStoreVersionLocalizations/… → 409 {"detail":"The name 'Flowr' is already being used"}
  stopped: 2 of 3 done
[изменившиеся области в формате look; новые вкладки, диалоги, редиректы]
```

В ответ попадают только изменяющие запросы (POST/PUT/PATCH/DELETE) к сайту страницы и его API. Аналитика и телеметрия отфильтровываются эвристикой. Для ошибок 4xx/5xx добавляется начало тела ответа.

### `navigate(url | "back" | "forward" | "reload", { screenshot? })`
- Ждёт реального содержимого: основная область не пустая, сеть затихла, нет спиннеров. Если предел ожидания достигнут, сообщает `⏳ loading`, а не делает вид, что всё готово.
- Сообщает о редиректах: `→ redirected to /signup`.
- Если на странице есть несохранённые правки (диалог «Leave site?»), не уходит молча, а сообщает об этом.
- Возвращает состояние в формате `look`.

### `read({ scope?, as: "text" | "table" })`
- `text`: чистый текст области, диалога или контейнера, без навигации и лигатур иконок. Если текст обрезан, это явно указано.
- `table`: строки × столбцы, действия и чекбоксы привязаны к подписи строки, фильтр по тексту строки.

### `read_api(url, { pick? })`
GET-запрос из контекста страницы, с её сессией и куками. Возвращает JSON, `pick` позволяет оставить нужные поля. **Только GET**, поэтому harness может разрешать его без вопросов. Это единственный источник правды, когда UI расходится с сервером (`FAILED` у скриншотов, `MISSING_METADATA`).

### `zoom(target | region)`
Детальная картинка элемента или области.

### `tabs({ list | switch | close | new })`
Список вкладок с типом (вкладка или popup), размером и opener.

### `eval(js)` — последнее средство (D-8)
Произвольный JS на странице. В описании для агента: использовать, только если ни `look`/`read`/`act`/`read_api` не подходят.

## Внутренние механизмы

- **Стабилизация:** нет активных fetch/XHR 300 мс, нет мутаций DOM 200 мс, нет видимых спиннеров и скелетонов. Предел 5 с для действия, 15 с для navigate. Анимации меню ждём через `transitionend`/`animationend` или стабильность прямоугольника элемента.
- **Номера:** WeakRef-карта плюс отпечаток элемента (роль, имя, путь контекста), чтобы найти его заново после перерисовки.
- **Обход:** iframe и shadow DOM. Определение слоёв: `dialog`/`aria-modal`, inert, перекрытие через `elementFromPoint`.
- **Скриншот:** таймаут около 3 с, при сбое отдаём только текст. Эмуляция фокуса, фиксированный viewport.
- **Сеть:** CDP Network пишет с момента подключения, запросы привязываются к шагу по времени.
- **Транспорт:** автоматическое переподключение. Ошибка транспорта не выдаётся за ошибку действия, в ответе явно сказано «неизвестно, выполнен ли клик».
- **Секреты:** скрываются только в полях паролей и карт.
