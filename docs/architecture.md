# Архитектура

Статус: обсуждение, кода ещё нет. Решения с обоснованиями см. в [decisions.md](decisions.md).

## Цель

Агент только принимает решения. Для этого ему нужно:
1. Видеть, что показывает сайт: скриншот, где у интерактивных элементов есть номерные метки.
2. Понимать, где элемент и к чему он относится: компактный список элементов с контекстом (диалог, секция, заголовок, подпись поля).
3. Действовать без селекторов и координат: «нажать 16», «нажать "Далее"», «заполнить {14: "50", 22: "..."}».

Структура DOM, селекторы, консоль и сеть агенту не показываются.

## Схема

```
Claude Code ──stdio/MCP──> agent-click (Node/TS, один процесс) ──CDP──> Brave пользователя
```

Компоненты внутри сервера:
- **Подключение**: читает `DevToolsActivePort` и подключается через `puppeteer-core`. Allow один раз на сессию.
- **Слой восприятия** (основная сложность): сбор интерактивных элементов в видимой области, их имён и контекста, стабильные номера; скриншот с метками.
- **Действия**: клик, заполнение и выбор по номеру или тексту через доверенный CDP-ввод.
- **Ожидание стабилизации**: после действия ждём, пока сеть и DOM затихнут, и сразу возвращаем новое состояние или дифф.

## Принципы

- Меньше циклов «вызов → ответ»: пакетные действия, состояние возвращается автоматически после действия.
- Меньше токенов: только видимая область, только интерактивные элементы, дифф вместо полного снапшота, скриншот под бюджет токенов.
- Никаких фиксированных пауз: ждём событий, а не таймеров.

## Открытые вопросы

1. **API инструментов для агента**: набор вызовов, что каждый возвращает, когда возвращать картинку, а когда только дифф. *Черновик v1: [api-draft.md](api-draft.md). Приняты D-5, D-6, D-7, остальное на обсуждении.*
2. **Сбор элементов** — *решено, D-9; пункты д и з проверить на практике*. Подвопросы:
   - а) источник данных: свой JS в странице, CDP Accessibility, CDP DOMSnapshot или комбинация; вычисление имён по спецификации accname;
   - б) что считать интерактивным: div с обработчиком клика (эвристика `cursor:pointer`);
   - в) **неинтерактивный текст**: статусы, цены, бейджи («Черновик», «FAILED», «PLN 244.99») — показывать ли их в `look`;
   - г) контекст элемента: из чего строится путь «диалог › секция › группа», какой глубины;
   - д) видимость, слои, перекрытия;
   - е) нумерация: стабильные растущие номера или перенумерация при каждом `look`;
   - ж) iframe: same-origin и cross-origin (OOPIF), shadow DOM;
   - з) дифф после действия и порог «значительного изменения» для auto-скриншота;
   - и) производительность и лимиты размера вывода.
3. **Формат представления**: вид списка элементов с контекстом, отрисовка меток, чтобы не закрывали интерфейс.
4. **Демон против одного процесса**: если Allow на каждую сессию будет мешать.
5. **Безопасность**: изоляция вкладок агента. Подтверждение рискованных действий не нужно, это делает harness (D-7).
